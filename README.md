# InterpreCoach Project Knowledge Base for Gemini

This document provides the definitive product, technical, and design specifications for the **InterpreCoach browser extension**. All generated code, content, and design mockups must adhere strictly to these guidelines. This is the single source of truth for the InterpreCoach product.

## 1. Product & Feature Specifications

### Core Product Identity

* **Product Name:** **InterpreCoach**
* **Product Type:** An intelligent, real-time AI assistant delivered as a **browser extension**.
* **Core Mission:** To act as a discreet "co-pilot" for medical interpreters during live sessions, enhancing their accuracy and confidence, and providing elite, ethics-based QA feedback post-session.

### User Interface & Design Philosophy

* **Layout:** The UI must be a **sleek, non-intrusive overlay** that integrates seamlessly with existing interpreting platforms without obscuring the primary interface.
* **Design Language:** Modern, clean, and minimalist, prioritizing clarity and at-a-glance readability.

### Detailed Feature Breakdown

#### Feature 1: Live Session Toolkit
* **Live Transcription:** Provides a real-time, scrolling transcript of the conversation.
* **Multi-Modal Terminology Support:** Automatically detects medical terms and provides a toolkit with:
    * **Spanish Translation:** The precise medical equivalent.
    * **English Pronunciation:** A phonetic guide and audio playback icon.
    * **Concise Definition:** A brief, easy-to-understand definition.
    * **Illustrative Image:** A relevant medical image (e.g., anatomical diagram) when appropriate.
* [cite_start]**AI-Powered Key Insights:** A dedicated UI section displays real-time summaries of critical information, focusing on **storytelling elements, medication dosages, and patient symptoms**.
* **Integrated Notes Section:** A simple text area for interpreters to manually type their own notes during the session.

#### Feature 2: Post-Session Quality Assurance (QA) Feedback
* **Functionality:** After a session ends, InterpreCoach generates a comprehensive performance feedback report. This report is designed to be objective and educational, grounding its analysis in established professional standards.
* **AI Engine:** The feedback is generated by a **specialized, pretrained LLM**. The prompt for this LLM is based on the "interprecoach-QA feedback" model.
* [cite_start]**Core Training Data for LLM:** The LLM is to be trained exclusively on the **official codes of ethics and standards of practice** from the following four leading authorities to avoid hallucinations and ensure industry relevance[cite: 4]:
    1.  **IMIA** (International Medical Interpreters Association)
    2.  **NBCMI** (National Board of Certification for Medical Interpreters)
    3.  **CCHI** (Certification Commission for Healthcare Interpreters)
    4.  **NCIHC** (National Council on Interpreting in Health Care)
* **Feedback Design & Method:** The visual layout and content structure of the feedback report must be modeled after the **InterpreBot feedback demo**. [cite_start]It should include a performance overview (Accuracy, Tone, Speed), a list of Strengths and Weaknesses, and actionable Recommendations, as detailed in the "Design of front end feedback QA" document.

## 2. Technical & Architectural Directives

### Frontend (Browser Extension)

* **Technology Stack:** **React 18** with **TypeScript**.
* **Styling:** **Tailwind CSS**, encapsulated to prevent style conflicts.
* **Manifest File:** Generate a `manifest.json` (Manifest V3) for a Chrome Extension.

### Backend & API Integration

* **Architecture:** The extension is the client; all intensive processing is offloaded to serverless **Google Cloud Functions**.
* **API Endpoints:**
    * `/api/ai/assist`: Manages the live session functionalities.
    * `/api/feedback/analyze`: Submits session data for QA analysis. The request to this endpoint should only contain the specific transcript sections relevant for feedback.
    * `/api/feedback/:sessionId`: Retrieves the generated QA feedback report.

### **Data Privacy, Security & Storage (Crucial Mandate)**

* **No Audio Storage:** The system **must not save or store any audio** from the interpreter sessions. Audio is processed in-memory for live transcription and immediately discarded.
* [cite_start]**Ephemeral Transcript Storage:** The full transcript of a session is held only in transient, in-memory storage during the session. [cite_start]After the session concludes, **only the specific, small sections of the transcript that are necessary for generating QA feedback are stored**.
* [cite_start]**Auto-Deletion:** All stored transcript snippets must be set to **auto-delete** after the feedback report has been generated and delivered to the user (e.g., using a Redis TTL of 24 hours or less). This ensures user privacy and data minimization.
* [cite_start]**Anonymization:** Any data used for analysis must be fully anonymized to protect patient (PHI) and interpreter (PII) privacy.
